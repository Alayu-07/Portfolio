# Alayu Legesse Siyfu

A fast, accessible, static portfolio. Vanilla HTML + CSS + JS (ES modules), no framework.
All content is pre-rendered into `index.html` from a single data file, so the site works with
JavaScript disabled and is fully crawlable.

## Project structure

```
.
├── index.template.html      ← markup source: sections, header, footer (paired <!--#slot--> markers)
├── index.html               ← generated by `npm run build` from the template + data.js (never edit)
├── 404.html                ← custom not-found page
├── robots.txt              ← generated by the build
├── sitemap.xml             ← generated once `siteUrl` is set
├── manifest.webmanifest    ← PWA/icon manifest
├── _headers                ← Cloudflare Pages / Netlify header rules
├── netlify.toml , vercel.json
├── css/style.css           ← design system (tokens → layers → components → print)
├── js/
│   ├── data.js             ← SINGLE SOURCE OF TRUTH — edit this
│   ├── theme-init.js       ← ~200 B, applies the saved theme before paint
│   └── main.js             ← progressive enhancement (nav, motion, filters, form)
├── assets/
│   ├── cv/                 ← put your CV PDF here
│   ├── fonts/              ← self-hosted variable woff2 (latin subset)
│   ├── img/                ← optimised photos, favicons, og.jpg
│   └── original/           ← your untouched originals (never overwritten)
├── scripts/                ← build / image / check / verify helpers
├── docs/                   ← audit evidence, Lighthouse reports, screenshots
└── AUDIT.md , WHAT-I-NEED.md
```

Deployment target is the **repo root** — no build output directory to configure.

## Quick start

```sh
npm install          # once (dev-only tools: sharp, puppeteer-core, axe-core, prettier)
npm run dev          # http://localhost:4173
```

The site must be served over HTTP (not `file://`) because `js/main.js` is an ES module.
`npm run dev` starts a tiny zero-dependency static server.

## Edit your content

Everything you'd normally change lives in **`js/data.js`** — name, headline, availability,
contact details, social links, skills, experience, education and projects. Then:

```sh
npm run build        # writes the content into index.html (idempotent, safe to re-run)
npm run check        # contrast + SEO + accessibility sanity checks
```

Any field that is an empty string or empty array is **hidden** on the site, so nothing looks
broken while you gather links, dates or screenshots. Anything marked `TODO` is listed in
[WHAT-I-NEED.md](./WHAT-I-NEED.md).

### Changing the layout instead of the content

Markup lives in **`index.template.html`**: sections, headings, nav, form and footer. Content
slots are paired markers — `<!--#slotName-->…<!--/#slotName-->` — and `npm run build` replaces
whatever is between them with output from `js/data.js`, then writes `index.html`. The template is
never written to, so a build can always be re-run from a clean state. Keep both halves of every
marker pair: a lone `<!--#slotName-->` with no closing `<!--/#slotName-->` is silently skipped.

## Add a project

Add an object to the `projects` array in `js/data.js`:

```js
{
  title: "My project",
  category: "web",                 // used by the filter chips (web / app)
  description: "One sentence for the card.",
  problem: "What problem it solves.",
  built: "What you actually built.",
  role: "Designer & developer",    // be specific and honest
  stack: ["React", "Node.js"],     // TECHNOLOGIES — leave [] until you're sure
  tags: ["Community", "Q&A"],      // domain words shown as pills
  features: ["Feature one", "Feature two"],
  learnings: "One honest sentence.",
  live: "https://…",               // empty ⇒ "case study in progress" shown
  repo: "https://github.com/…",
  image: "assets/img/projects/my-project.webp",
}
```

Then `npm run build`. Technology chips render **only** when `stack` has entries, and the
Live/Source buttons render **only** when the URL exists.

## Add screenshots

1. Take a 16:10 screenshot (1600×1000 or larger).
2. Save it at `assets/img/projects/<name>.webp` (or `.jpg`/`.png`).
3. Set `image: "assets/img/projects/<name>.webp"` on the project and run `npm run build`.

The image appears both on the card cover and inside the case study, and the "Screenshot coming
soon" badge disappears automatically. `npm run images` also generates responsive
AVIF/WebP/JPEG variants for your own photos.

## Set up the contact form

The form works out of the box by opening the visitor's email app. For real delivery, create a
free endpoint and paste the URL into `js/data.js`:

**Formspree (default)**

1. Create a form at <https://formspree.io> → copy the URL, e.g. `https://formspree.io/f/abcdwxyz`.
2. In `js/data.js`: `contact: { formEndpoint: "https://formspree.io/f/abcdwxyz", formProvider: "formspree" }`.
3. `npm run build`.

**Web3Forms**

1. Get an access key at <https://web3forms.com> (the key is _publishable_ — it is safe to commit).
2. In `js/data.js`: `formEndpoint: "https://api.web3forms.com/submit"`, `formProvider: "web3forms"`.
3. Add `data-web3forms-key="YOUR_KEY"` to the `<form id="contactForm">` tag in `index.html`.

The form includes a honeypot field, inline validation (`aria-invalid` + `aria-describedby`),
loading/success/error states, and a mailto fallback. **Never** commit a private API key — none
is needed for either provider. If you change providers, update the `connect-src` allow-list in
the CSP (in `index.html`, `_headers`, `netlify.toml`, `vercel.json`).

## Images & fonts

```sh
npm run images                                    # responsive AVIF/WebP/JPEG, favicons, og.jpg
node scripts/download-fonts.js                    # refresh the self-hosted woff2 files
```

Originals are preserved untouched in `assets/original/`. Your portrait is never generated or
altered — only re-encoded and resized.

## Checks & verification

```sh
npm run check      # contrast ratios (WCAG AA), TODO inventory, HTML/SEO/a11y sanity
npm run verify     # screenshots at 320→1440 px in both themes, axe-core report, no-JS check
npx lighthouse http://localhost:4173 --view    # Lighthouse (needs `npm run dev` running)
```

Reports are written to `docs/` — see `docs/verification.md` for the latest numbers.

## Deploy

### GitHub Pages

```sh
git init && git add -A && git commit -m "Portfolio v2"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

Then **Settings → Pages → Source: deploy from branch → `main` / root**. Your site appears at
`https://<you>.github.io/<repo>/`. The build uses relative asset paths, so sub-path hosting works.
Add a `.nojekyll` file (already present) so files like `_headers` are published.

### Netlify

- **Drag & drop:** app.netlify.com → _Add new site → Deploy manually_ → drop the folder.
- **Git:** _Add new site → Import from Git_ → build command: _(leave empty)_ → publish
  directory: `.` — `netlify.toml` already sets `publish = "."`.

### Vercel

`vercel --prod` (or import the repo). No framework preset, no build command, output directory `.`.
Header rules live in `vercel.json`.

### Cloudflare Pages

Connect the repo → **Framework preset: None** → Build command: _(empty)_ → Output directory: `/`.
`_headers` is applied automatically.

**After your first deploy:** put the live URL into `siteUrl` in `js/data.js`, then
`npm run build && npm run check`. That enables the canonical URL, the absolute `og:image`,
and generates `sitemap.xml`.

## Custom domain

1. Buy a domain (Namecheap, Cloudflare Registrar, Porkbun…).
2. **Netlify/Vercel/Cloudflare:** _Domains → Add custom domain_ → follow the DNS instructions
   (usually a `CNAME` to your provider, or `A`/`AAAA` records for an apex domain).
3. Enable HTTPS (automatic on all three) and turn on _Force HTTPS_.
4. **GitHub Pages:** add a `CNAME` file containing your domain, then set the same domain under
   _Settings → Pages → Custom domain_, and enable _Enforce HTTPS_.
5. Update `siteUrl` in `js/data.js` and `npm run build`.
